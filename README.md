# **Тикет 0: «Парсер лога осады»**

> **От кого:** *Соня*
>
> **Контекст**: *Привет! Мы запустили механику осады замков на сервере GAME. Старый скрипт расчета осадного урона регулярно падает, ломая запись в БД. Напиши новый парсер.*

**Входные данные:**

Из логов прилетает строка формата: [Тег_Гильдии]Игрок | Базовый_урон | Состояние_орудия | Количество_баффов.

Пример:  `[EAGLE]Dark_Angel | 1540.5 | Active | 2`

Что нужно сделать:

- Отдели тег гильдии от имени игрока
- Вычисли итоговый урон по формуле: Базовый_урон * Множитель_состояния * (1 + 0.15 * Количество_баффов).
- Множитель состояния: если орудие Active = 1.5, если Broken = 0.5.
- Выведи строку: Игрок <Имя> из гильдии <Тег> нанес <Урон> по воротам. (Урон округлить до 2 знаков).

Примечание: Если баффов нет, в логе может быть пусто (например, ... | Active | ). Пустота означает 0 баффов.

[siege_log.txt](siege_log.txt)

## Как сдавать

Код пишем в `siege.py`. Запуск:

```sh
python3 siege.py siege_log.txt
```

Путь к логу приходит первым аргументом, результат печатаем в stdout, по одной
строке на выстрел. Пушим в `main`: на каждый push GitHub прогоняет проверки, их
результат виден во вкладке **Actions** и в релизе `submit/...`.

Проверок две:

1. Скрипт отрабатывает весь `siege_log.txt` и не падает.
2. Строка-пример из ТЗ считается верно.

Всё остальное в логе — на твоё усмотрение. Если что-то непонятно, спроси Соню
(то есть преподавателя). Это лаба-разминка, баллов за неё нет, но без неё
следующие лабы не примут: она проверяет, что доступ к репозиторию, push и
автопроверки у тебя работают.
